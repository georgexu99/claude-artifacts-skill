Instructions to replicate this site

Paste this prompt into your ~/.claude/CLAUDE.md (or a single session) and Claude will build and mirror artifacts the same way, to your own GitHub Pages site (<you>.github.io/claude-artifacts/, or pages.<host>/<you>/claude-artifacts/ on GitHub Enterprise).

When I ask you to create, update or share an Artifact, publish it with the Artifact tool as usual, then mirror the same HTML file to my GitHub Pages site so people without claude.ai access can open it. Use the claude-artifacts skill for the mirror: git clone {{SKILL_URL}} ~/.claude/skills/claude-artifacts, then run its publish.sh. It talks to GitHub through gh api only; no git clone of the site repo is needed.

Where it lives

  • Repo <login>/claude-artifacts, branch gh-pages (also the default branch), Pages serving gh-pages from /, plus an empty .nojekyll. <login> is gh api --hostname <host> user --jq .login.
  • On github.com the site is https://<login>.github.io/claude-artifacts/. On GitHub Enterprise it is https://pages.<host>/<login>/claude-artifacts/. Set ARTIFACTS_GH_HOST for a GHE host; ARTIFACTS_OWNER and ARTIFACTS_REPO override the owner and repo name.
  • First use: run publish.sh init. It creates the repo (public unless ARTIFACTS_PRIVATE=1), the gh-pages branch, .nojekyll, and enables Pages. If enabling Pages fails, tell me to switch it on under Settings → Pages. Pages on a private github.com repo needs a paid plan.

Layout per page

  • <slug>/page.html: the artifact, unchanged except that <!doctype html> and <meta charset="utf-8"> are prepended if they're missing from the first 2 KB. claude.ai adds them for you, but Pages doesn't, and without them the page renders in quirks mode as Latin-1.
  • <slug>/index.html: a small shell with a left sidebar and the page in a full-height <iframe src="page.html">. It forwards the outer #hash into the iframe and keeps the two in sync, so deep links work.
  • manifest.json at the root: an array of {slug, title, emoji, project, group, state, next, nav, summary, claude_url, created, updated}, newest updated first. created survives updates.
  • A shared site.css and site.js. The JS fetches manifest.json at load time, so adding a page never requires rewriting the other pages.
  • Sidebar: search, then a Monitoring section and a Pull requests section for pages with nav set (monitoring, prs), then one collapsible section per group with a state dot per page and the current page highlighted.
  • Landing page (root index.html): a hero with page counts, a "Come back to" rail of Open/Waiting pages showing their next line, a "Recently updated" rail, a state filter, and one card section per group. Open/Waiting pages untouched for 30+ days get a "stale" pill.
  • Light and dark themes via prefers-color-scheme, plus a theme toggle remembered in localStorage. The sidebar collapses behind a toggle on narrow screens.

Commands

  • publish.sh publish <file> --title … [--slug …] [--emoji …] [--summary …] [--group …] [--state …] [--next …] [--nav monitoring|prs] [--claude-url …] [--no-open]
  • publish.sh set <slug> --state … --next … [--touch] for metadata only; publish.sh list; publish.sh rm <slug>; publish.sh rebuild after editing the site templates.
  • Run commands that rewrite manifest.json (publish, set, rm) one at a time, never in parallel.

Before publishing: the visibility check

  • The mirror is readable by anyone who can see the Pages site. On github.com that is the public internet unless the repo is private on a paid plan; on GitHub Enterprise it is usually everyone with an account on that instance. Either way it is much wider than a private claude.ai artifact. Skip the mirror, and say so in one line, if the page has customer data, personal info, unannounced plans or secrets.
  • publish.sh refuses on credential patterns (xox[abposr]-, AKIA…, gh[pousr]_…, -----BEGIN … PRIVATE KEY-----, JWTs). Pass --force only after I confirm it's a false positive.
  • Mirror single-file HTML only. Inline any supporting files first. Don't mirror typed artifacts such as Docs or Slides.
  • If the page uses window.claude.* (db, live data, ask-Claude), that part is dead on Pages. Mirror it only if the page still makes sense as a static snapshot.

Conventions

  • Slug: the title in kebab case, max 60 characters. When updating an artifact, reuse its existing slug so the URL stays the same (check publish.sh list).
  • group is the topic the site groups by, emoji first (🧪 Build experiments). Reuse an existing group's exact spelling; a new spelling makes a new group. project is the repo path, metadata only.
  • state is Open (default), Waiting (on someone else), Done or Dropped; next is one line on what happens next. Keep both honest: flip a page to Done when its work lands, Waiting when it stalls on a review. Metadata-only changes don't bump updated.
  • title and summary match the Artifact's title and description, and claude_url is the claude.ai link.
  • Afterwards, give me both links, one per line.
